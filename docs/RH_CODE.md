# RH Code 使用指南

RH Code 是 PCL RH 的项目工作区与 AI Harness。一个项目把源码文件夹、多个 AI 对话和开发目标组织在一起，支持通用文本源码，不要求使用某个模组模板。顶部紫色入口打开工作区，旁边的橙色入口管理插件；百宝箱位于「设置」。

## 加载与休眠

启动器启动时不加载 RH Code 工作区及其插件实现，首次打开紫色或橙色入口才加载。离开页面后暂时保留工作区，切回可以继续编辑。

离开至少 10 分钟、最近工作活动结束至少 5 分钟后，工作区会尝试保存对话草稿、布局和已编辑的源码，再从内存释放界面、编辑缓存及 RH Code 插件实例。源码自动保存使用与手动保存相同的文件指纹检查；冲突或保存失败时保留工作区和内容。

运行中的 AI、尚未完成的请求、未提交的设置、打开的对话框或插件声明的活动工作都会阻止休眠。AI 暂时没有输出不代表任务结束。后台引擎也会检查任务、子进程和待处理操作，确认空闲后退出，下次使用自动启动。已保存的 AI 预设继续有效。

休眠不删除项目、插件或程序文件。再次进入会读取已保存的项目、布局和对话。浏览器已导入的脚本模块仍可能保留在模块缓存中；释放的是活动实例、工作区数据和空闲后台进程。

## 创建与打开项目

点击「新建项目」，填写名称并选择一个已有文件夹。空文件夹可用于新的模组工程，已有文件夹可用于阅读和编辑源码。项目登记不会移动文件夹。项目列表可以搜索名称和路径，工作区顶部可以直接切换项目。

默认登记 Fabric 和 NeoForge 目标。目标描述开发意图，不代表两个加载器的工程已经生成或编译完成。可以在「构建与测试」区域增加 Minecraft 版本，并分别选择加载器。

旧制作器和搬运器项目可从项目列表的「旧版项目」打开，继续使用兼容界面及原有任务产物。新工作区采用独立的项目记录，不会自动转换旧项目。

## 调整区域

每个区域顶部选择它显示的内容：内容图谱、文件图谱、源码、AI 对话、对话列表、构建与测试、版本迁移、改动审阅或任务输出。

- 区域操作菜单可左右或上下拆分、交换区域、关闭区域。
- 拖动分隔线调整大小；分隔线也支持方向键。
- 最大化按钮暂时聚焦一个区域，再次点击还原。
- 「布局」提供创作、并行对话和源码三种起点，并可保存、重命名和删除自己的布局。
- 保存的布局可跨项目套用，最多保留 32 个。导出生成可复制的 JSON；导入支持粘贴 JSON 或选择文件。
- 支持设置的组件会在区域标题旁显示齿轮。「项目概览」可调整是否显示目录，同一组件的不同区域各自保存设置。

布局随项目保存。关闭区域不删除对话、源码或任务；源码中尚未保存的编辑在当前启动器会话中保留。每个项目最多显示 12 个区域。

导出的布局只包含区域类型、位置和尺寸，排除文件路径、对话绑定与组件数据。套用时重新分配区域身份，AI 对话区域按当前项目的对话顺序绑定。组件暂不可用时保留区域占位，重新启用插件后恢复。组件显示出错时，可在该区域重新加载。

内容图谱目前按源码、资源和项目配置分组；文件图谱提供可折叠的目录树。它们尚未解析 Java 语义或 Minecraft 注册关系。

## 对话与 AI

左下角设置按钮管理共享 AI 预设、密钥和任务预算。保存并选中预设后，在项目对话中提交请求即可自动启动引擎。

高级设置中的模型调用、工具调用、单次输出、任务时长和估算费用上限均可设为 `0`，表示不设该项任务限制。输出仍遵循模型容量；预设修改用于新任务，运行中的任务保留原配置。

项目支持多个独立对话，同一对话一次运行一个任务，共享引擎最多运行两个任务。任务归属项目和对话，切换区域或页面不会取消它。停止按钮取消当前任务。

对话名旁的铅笔可重命名，历史和任务归属保持原值。输入区的「引用」可搜索并选择项目文本文件，最多 20 个；点击文件标签上的关闭按钮移除引用。引用表示本轮关注点，AI 仍可按需查看项目快照中的其他文件。

「上下文」中可保存当前对话的记要或目标，以及各对话共用的项目说明。每项最多 8000 字符、24000 UTF-8 字节。发送请求前会保存这些编辑；保存失败或保存期间又有新编辑时，保留内容并暂停提交。运行中的任务保留原上下文，后续修改用于下一轮。

| 模式 | 可用能力 |
| --- | --- |
| 询问 | 列出文件、按需读取和检索，回答项目问题 |
| 规划 | 只读分析，并记录本轮计划 |
| 执行 | 记录计划，提出文件新增、修改或删除建议，等待用户审阅 |

对话中可查看实时回答、文件读取和工具状态、计划及错误。`Ctrl+Enter` 提交请求；停止按钮会取消当前任务。停止或失败的任务所留下的建议不能应用。

初始上下文最多投影 8 条近期消息，每条截取最多 1800 字符，另有完整输入的字节预算；完整历史仍保存在项目记录中。AI 可以检索和分页回查本轮捕获的旧消息，长消息支持继续读取后续内容。初始源码摘要只提供起点，引用文件优先进入摘要，其余内容按需读取。

可回查的历史是至多 1024 条完整消息、总计 1 MB 的连续近期片段；源码接近传输上限时，片段可能更短。工具会说明捕获范围、缺失数量和截断，不把未捕获的讨论当作已读内容。项目说明和对话记要另行保存。这是确定性的上下文投影，不是自动生成的长期记忆。

当前 Harness 支持通用项目源码改动；旧制作器继续保留 Fabric 模板能力。Shell 执行、项目构建、打包和启动游戏测试尚未接入，AI 的回答或计划不代表这些检查已经通过。

## 源码与审阅

从文件图谱打开文本文件，修改后点击保存。保存检查文件内容指纹：磁盘文件被其他编辑器修改时，会拒绝覆盖，并保留原内容备份。文本文件上限为 1 MiB。

提交 AI 请求前会保存当前项目中已编辑的源码；保存冲突时保留编辑并停止准入。Rust 随后捕获一份独立的源码快照，文件工具只读取这份快照。提交后的新编辑不会改变已运行任务的输入。

执行模式生成的建议显示在对话和「改动审阅」区域。检查文件列表和差异后点击「审阅并应用到项目」。原生层会复核项目目录身份、完整快照和文件内容指纹；项目在任务运行期间发生变化时会拒绝应用，应根据最新源码重新生成建议。较长的差异预览会明确标出截断；文件列表不完整时无法应用。

应用前保留原文件备份。多个文件逐个原子发布，并记录持久事务；中途退出后，会在下次捕获、保存或应用时检查并恢复未完成事务。如果文件已被外部修改，恢复会保留相关文件和备份并报告冲突。已经应用的同一建议可安全重试，不会覆盖之后的新编辑。

普通项目允许提出手写文件的改动，仍需用户确认。带旧 Maker 保护记录的项目继续保留锁定文件和指纹不符文件的保护；不会把缺失或损坏的保护记录自动视作授权。旧版「采用源码」操作继续只发布到空文件夹。

快照最多包含 1000 个 UTF-8 文本文件、合计 16 MiB，每个文件上限 1 MiB。隐藏路径、常见依赖缓存和构建产物不参与；二进制、过大及非普通文件也会跳过，并在模型上下文中说明缺失范围。目录深度上限为 12，枚举上限为 12000 项。超过快照范围时，请选择更窄的项目文件夹。提案单次输入另有 1.8 MB 上限。

## 内置与社区插件

橙色插件入口中，内置模块可按依赖启停，核心项目服务与设置必须保留。插件停用时其区域显示占位，重新启用后恢复原区域；对话和文件缓冲区由项目服务持有。

每个内置插件可独立提供组件、组件设置、命令和布局。插件页显示运行状态及贡献清单；加载失败时可以重试，依赖未就绪的模块不会运行。

内置模块也可声明 AI 工具：文件读取属于文件模块，上下文与历史属于对话模块，计划和建议属于改动审阅模块。详情中可查看工具及其适用模式。新任务保存启用模块与具体工具清单；之后增加工具不会扩大旧任务的范围。停用模块影响后续任务，已经运行的任务保留捕获范围；应用建议时仍会复核原生模块状态。

插件作用范围分为「启动器」「RH Code」「两者」。启动器插件随本体加载，RH Code 插件随工作区加载、休眠时释放；两者通用的插件在启动器存活期间保留同一个实例。作用范围由插件声明决定，启用与停用仍遵循依赖关系。目前内置模块均属于 RH Code，旧版社区声明型插件的权限机制保持独立。

内置模块使用 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 所采用的 Cordis 生命周期机制。RH Code 接入了实际的 `@deepseek-ai/cordis`，Agent 执行由现有 Pi 适配器负责；没有装载 DSH 的整套默认插件，也不声明兼容 DSH 插件包。

社区入口继续使用声明型插件和原生权限管理，不执行第三方 JavaScript。市场暂未开放。内置模块的能力声明不等于社区插件授权，Cordis 本身也不是代码执行沙箱。旧格式范围见[兼容功能说明](EXPERIMENTAL.md)。

开发者可继续阅读[RH Code 模块结构](RH_CODE_ARCHITECTURE.md)及[内置插件开发](RH_CODE_PLUGINS.md)。
