# 使用指南

PCL RH 支持下载安装 Minecraft 原版，也可以启动已有的游戏版本。首次运行前，请按[README](../README.md#构建与运行)完成构建。

界面使用配套鼠标和右键菜单。文本框可右键复制、剪切、粘贴或全选，也可用原有快捷键；`Shift+F10` 打开菜单，方向键选择，`Esc` 关闭。游戏目录的右键菜单提供目录管理操作。

## 选择游戏目录

1. 打开「启动 → 实例选择」。
2. 点击「添加已有文件夹」，通过系统文件夹选择器选择已有的 `.minecraft` 目录，或一个已创建的空目录用于安装原版。
3. 在左侧文件夹列表中切换目录，选择要运行的实例。可以输入实例名称进行搜索。

每个目录分别记住所选实例、内存和 Java 覆盖设置。通过文件夹右侧的菜单可改显示名称、调整顺序或移除登记；这些操作不会改名或删除磁盘上的游戏文件。

临时断开或不可读的目录仍保留在列表中，恢复访问后可重新选择。已从磁盘删除的目录也可以移除登记；移除当前目录时优先切换到相邻的可用目录。至少保留一个登记，若只剩失效目录，请先添加其他目录。正在使用或仍有未完成恢复记录的目录需要先结束任务或完成恢复。

个别损坏的实例会单独显示提示，其他实例仍可使用。

文件夹选择器使用 XDG Desktop Portal。系统需要运行 `xdg-desktop-portal` 及适合桌面环境的文件选择器后端。取消选择不会添加目录；选择器不可用时会显示提示。

如果没有显示实例，请检查所选目录中是否有 `versions` 文件夹。

## 安装游戏与加载器

1. 先在「启动 → 实例选择」中选择目标游戏目录。
2. 打开「下载」，展开正式版、预览版、远古版或愚人节版分组。
3. 选择版本，在顶部填写实例名称。需要模组加载器时，展开 Fabric、Forge 或 NeoForge 并选择版本；三个加载器只能选择一个。未手动改名时，选择组件会自动补充实例名称；手动填写的名称会保留。
4. 点击「开始下载」。启动器会从官方源获取游戏本体、依赖库、资源及 Linux 原生库，并校验下载文件。加载器的启动配置与必要文件会一起安装。
5. 完成后，实例会加入开始下载时所选的目录，默认成为该目录的所选实例；可在「设置 → 管理」关闭自动选择。切回该目录后，返回「启动」开始游戏。

「任务管理」显示原版信息、支持库、资源文件和所选组件的下载与安装步骤，以及总进度、下载速度和剩余文件。悬停在任务名称上可查看安装目录。任务卡片分别显示名称、目录、状态和取消按钮；全部任务成功或取消后自动返回原页面，失败的任务保留供查看，可用卡片右上角关闭按钮收起记录。游戏安装、本地整合包安装、在线资源安装、资源另存和工具箱下载最多同时运行 4 项、等待 32 项。不同游戏目录可并行，同一或重叠目录按顺序执行；独立另存按实际目标文件判断冲突。每项任务内部仍可并发下载多个文件。

点击任务右上角的取消按钮后，启动器停止下载和组件处理，清理未完成文件，等待该项清理结束。清理过程中按钮会禁用；其他任务继续运行，全部任务结束后返回原页面。等待中的任务也可取消；若任务已经完成，保留完成结果。已校验通过的完整公共资源与依赖库可在重试时复用。安装任务进行时可切换目录浏览，目标目录保持不变；可继续提交其他下载，等待全部任务结束后才能启动游戏。改名、删除、更新、导出等文件事务仍需等待下载结束。正在安装或运行游戏的目录不能移除登记。

已有的同名实例不会被覆盖。已安装的 Minecraft 版本仍可选择，使用不同实例名称可另装一份。部分早期版本暂不支持自动安装，界面会显示原因。OptiFine、LabyMod 自动安装尚未开放。

Forge、NeoForge 自动安装支持现代官方安装器格式；旧版 Forge 安装器格式暂不支持，会保留已有实例并清理本次临时文件。

安装结果会显示所需 Java 主版本；游戏文件下载不包含 Java。请先在「设置 → Java」下载或添加对应 Java。Forge、NeoForge 安装时还需要对应的 Java 主版本执行组件处理，启动器会自动查找。

## 浏览安装包与社区资源

「下载 → 安装包」可浏览 Minecraft、OptiFine、Forge、NeoForge、Cleanroom、Fabric、Legacy Fabric 和 LiteLoader 的官方版本目录。点击版本分组展开列表，点击「打开官网」访问对应项目；LabyMod 的安装器通过官网提供。此处的单文件与安装器下载尚未开放；安装 Fabric、Forge、NeoForge 请从 Minecraft 版本选择页进入自动安装。

「下载 → 社区资源」可搜索 Modrinth 的模组、整合包、数据包、资源包和光影包。点击资源查看版本详情，并按游戏版本、加载器筛选；版本分组内可浏览必要与可选依赖，点击已解析的依赖资源行可进入它的版本详情。模组、资源包和光影可安装到当前所选实例，见下节。选择 Modrinth 整合包版本可直接下载、确认并安装为新实例，见下节。数据包安装、CurseForge 在线目录和世界目录尚未开放。保存的本地 ZIP / mrpack 可通过导入入口安装，见[导入本地整合包](#导入本地整合包)。

## 直接安装 Modrinth 整合包

1. 先选择目标游戏目录，再打开「下载 → 社区资源 → 整合包」中的项目详情。
2. 选择版本并填写新实例名称，点击确认。多文件版本可先关闭名称弹窗，在文件列表选择实际的 `.mrpack`，再点击「安装整合包」。
3. 等待整合包下载、SHA-512 校验及安装内容检查。核对游戏与加载器版本、可选文件、下载大小和阻止项；可修改实例名和可选内容后重新检查，压缩包无需重复下载。
4. 点击「开始导入」，在任务管理中查看安装进度。安装只创建新实例，不覆盖同名实例；完成后可从实例列表选择它。

下载与确认阶段可关闭弹窗取消，匿名暂存文件会释放。开始安装后，请在任务管理中取消；工作线程停止并清理后才释放目录。确认来源短期保留，过期需重新选择版本。官方压缩包上限为 512 MiB，游戏组件与清单格式沿用本地 Modrinth 导入的支持范围。

## 安装 Modrinth 资源

1. 在「启动 → 实例选择」选择目标目录和实例，退出游戏，等待正在执行的改名、删除、更新等文件事务结束。
2. 打开「下载 → 社区资源」的模组、资源包或光影包，搜索并打开项目详情。
3. 选择与目标 Minecraft 和加载器兼容的版本。在所选版本的文件列表中选择文件，点击「安装到实例」。多文件版本默认选择主文件，也可选择其他运行用文件。
4. 核对目标实例、必要前置、复用文件、下载大小和提示，点击「开始安装」。任务标题显示资源名称；任务管理显示信息检查、下载校验和文件提交。
5. 完成后，在目标实例的模组、资源包或光影列表中检查文件。资源包和光影仍需在游戏内启用；安装光影包不会自动安装光影引擎。

启动器重新读取官方项目、版本和文件数据，按声明的 SHA-512 与大小校验全部文件后统一提交。必要依赖会加入方案；可选依赖不会自动安装。无法解析的外部必要依赖、依赖循环、多版本冲突和不兼容资源会阻止安装，并显示原因。未知来源的本地文件不能完整参与项目冲突检查，方案会给出提示。

相同内容的已启用文件可复用。已禁用的相同模组不会自动启用；已有旧版本、同名不同内容或其他目标冲突也不会被覆盖，请先自行处理。需要更新已有 Modrinth 模组时，请使用下节的本地模组更新入口。资源位置遵循原实例的隔离规则，共享资源目录中的变更会影响使用该目录的其他实例。

可以为同一实例连续提交资源安装，它们按顺序执行。前一个任务新增了兼容资源，或已经安装了内容完全相同的必要前置时，后一个任务会重新核对并复用原确认。实例核心、原有文件、官方文件或依赖权限变化，以及新发现的冲突，会要求重新检查；不会自动覆盖或选择另一个前置版本。未知来源的新增文件不能自动证明兼容，也需重新检查。排队卡片从提交时显示所选资源名称。

未提交的确认超过 10 分钟或重启启动器后，需要重新检查方案。已经成功提交的队列任务会保留本次确认，等待时间不会使它失效；轮到任务时仍会重新验证。

取消会停止请求并清理本次未完成文件，任务结束后返回原页面；进入提交阶段后不能再取消。中断提交或清理失败时，在所在游戏目录点击「恢复资源安装或更新」，完成恢复后再操作或启动。遇到外部修改会保留内容并显示原因；不会通过覆盖冲突文件来完成恢复。文件操作需要支持匿名暂存的文件系统和 Linux 5.6 以上的目录校验能力，符号链接或单独挂载的目标目录可能被拒绝。

「下载文件」提供独立保存流程，见[独立保存社区资源文件](#独立保存社区资源文件)；「安装到实例」会写入已选实例的资源目录。

## 实例界面

「实例设置 → 修改」可重置支持的实例组件；「导出」可选择内容生成本地 ZIP。操作前需退出游戏，并等待其他文件任务完成。

本地资源列表支持搜索、排序、多选与详情查看。在线资源安装从社区资源详情进入；模组更新检测与恢复见[更新本地模组](#更新本地模组)。

空列表也可点击「下载新资源」，按当前游戏版本和加载器进入社区资源页。模组、资源包和光影列表均可手动刷新，读取从其他程序加入或移走的文件；当前目录的资源安装、更新等任务结束后，已打开的列表会自动重新读取。

## 重置实例组件

1. 打开「实例设置 → 修改」，点击已选加载器旁的叉号移除当前选择，再选择 Fabric、Forge 或 NeoForge 的兼容版本。全部移除则重置为原版。
2. 点击「开始重置」，核对当前组件和新方案，再确认。Minecraft 版本保持当前版本；Minecraft 版本修改暂未开放。
3. 在「任务管理」查看安装和核心替换步骤。重置保留实例名称、模组、配置、存档和其他游戏内容，核心 JSON/JAR 的原始备份保留在游戏目录内。

目前支持具有独立核心文件的原版、Fabric 和现代 Forge/NeoForge 实例。继承版本、被其他实例复用的核心、旧版或自定义启动布局会显示不能重置的原因。核心暂存需要文件系统支持 `O_TMPFILE`；支持库单独挂载在其他文件系统时，重置可能被拒绝，原核心文件会保留。

取消会清理本次暂存文件并保留原实例。若上次重置中途关闭，页面会提示「恢复实例重置」；恢复完成后再启动游戏。遇到外部修改或冲突时保留备份并显示原因。更换加载器后，现有模组仍需与所选加载器兼容。

## 导出本地 ZIP

1. 打开「实例设置 → 导出」，填写整合包名称和版本。
2. 勾选内容。资源包、光影包、截图和存档可以逐项取消选择；默认不勾选存档、截图和服务器列表。
3. 点击「开始导出」，核对文件数量、大小及提示，再通过系统保存窗口选择 ZIP 位置。使用新的文件名，并保存到游戏目录之外。

ZIP 包含游戏版本核心文件、所选游戏内容和整合包信息。高级选项「打包资源文件」还会加入本地资源和支持库；支持库可能包含同目录其他实例的依赖，其他平台的原生库仍可能需要下载。缺少所需文件时会显示原因。导出不修改原文件，取消会清理未完成 ZIP。打包期间源文件变化时，请重新检查后导出。

「保存配置」保存此实例的导出选择，「读取配置」恢复已保存的选择。模组个人信息按已知文件位置区分，自定义位置请在分享前检查。Modrinth 上传模式和打包启动器尚未开放；本地 ZIP 可用解压工具查看，也可按下节导入。

## 导入本地整合包

1. 在「启动 → 实例选择」选择目标游戏目录，点击左侧「导入整合包」。
2. 通过系统文件选择器选择本地 `.zip` 或 `.mrpack`；取消选择不会创建任务。格式按包内内容识别。
3. 填写新的实例名称，点击「确定」。核对格式、游戏版本、加载器、文件数量、大小与提示；有可选客户端文件时按需勾选。
4. 修改名称或可选项后点击「重新检查」。没有不支持项时，点击「开始导入」。
5. 在「任务管理」查看游戏组件安装、整合包文件校验与提交。完成后，切回目标目录选择新实例。

| 格式 | 当前支持范围 |
| --- | --- |
| PCL 本地导出 ZIP | 含 `pcl-export.json`，合并继承配置并按新名称生成核心文件；未打包的依赖可能仍需补齐 |
| Modrinth ZIP / mrpack | 含 `modrinth.index.json`，下载客户端文件、应用通用及客户端覆盖，支持原版、Fabric、现代 Forge / NeoForge |
| HMCL、MCBBS | 根据格式清单重建受支持的游戏与加载器，再导入包内内容；额外启动命令、自定义运行库或无法取得的外部文件会显示限制 |
| MultiMC / Prism | 含 `mmc-pack.json` 与实例配置，导入游戏内容并重建受支持组件；自定义补丁和启动命令暂不执行 |
| 完整游戏目录 ZIP | 含可识别的版本 JSON/JAR，复制已有核心、支持库、资源和游戏内容，合并版本继承；多实例歧义或缺少核心会要求处理 |
| 带启动器 ZIP | 根目录或唯一一层外包装目录含 `modpack.zip` / `modpack.mrpack`；也支持 HMCL 的 `.hmcl/modpack/` 精确布局，按内层实际格式检查和安装 |
| CurseForge ZIP | 识别 `manifest.json`；文件服务开放后，可按官方清单下载模组、资源包和光影。当前服务未配置时仍会阻止安装，作者限制或缺少官方下载信息的文件也会阻止完整安装 |

检查会读取整合包内容，必要时获取官方游戏和加载器信息；点击「开始导入」后才下载游戏与包内声明的运行文件，并创建新实例。Modrinth 的网络文件按大小、SHA-1 和 SHA-512 校验；包内文件也校验解压内容。CurseForge 本地 ZIP 在服务可用时重新核对精确文件编号、分发许可、URL、SHA1 和大小；清单中的可选列项也会完整纳入，确认页显示提示。MCBBS 清单中的 CurseForge 文件引用暂未接通。未知加载器、多加载器组合、未支持的下载来源与格式冲突会显示原因。第三方清单可有一层外包装目录；混合多个独立整合包的 ZIP 会被拒绝。

带启动器归档会自动检查唯一内包，确认页显示内层实际格式和内容，原始来源仍是所选外层 ZIP。只安装内层游戏内容；外层 Windows 启动器和 HMCL 配置保持在原 ZIP 中。最多接受一层嵌套，两个内包、与其他格式冲突或继续嵌套会被拒绝；内层是本启动器含 `pcl-export.json` 的旧导出格式时，请先提取内包再直接导入。内包的临时容量与检查数量有上限，达到容量时请等待检查完成或取消已提交任务，再重新检查。

客户端方案按 [Modrinth 格式说明](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack) 处理：必需文件默认选择，可选文件由你勾选，服务端专用文件排除；通用覆盖先应用，客户端覆盖随后应用，遮盖数量单独列出。下载大小为所选整合包文件的大小，游戏核心和支持库在任务中另行下载。

所有内容先在私有临时目录内构建、校验，再提交到新实例；已有实例和不同内容的公共文件不会被覆盖，相同内容的公共库与资源可以复用。原 ZIP / mrpack 保持原样，不导入启动器账号、设置或 Windows 启动程序。Modrinth 覆盖目录中可识别的 PCL `config.json` 与 `Setup.ini` 会在检查后忽略，并在安装预览中提示；不接受其他未知的启动器配置。完整游戏目录和本地导出仍可能缺少 Linux 原生库或其他依赖，导入完成不代表跨平台依赖已齐全。

Modrinth 和上述其他启动器格式可与下载任务一起排队：不同目录并行，同一或重叠目录顺序执行。PCL 本地导出 ZIP 沿用原本的本地事务流程，开始导入前仍需等待其他文件任务结束。游戏安装与加载器处理需要对应 Java；缺少时先到「设置 → Java」下载或添加，再重试整合包安装。第三方清单的私有根重建还要求内核启用 Landlock ABI 3（Linux 6.2+）和 openat2；缺少能力时会报错并清理，不继续沿未绑定路径安装。

修改实例名称、源文件或可选项后需重新检查；未提交的确认超过 10 分钟或重启启动器后也需重查。已经成功提交的任务保留确认，排队时间不会使它失效。已删除但尚未恢复的实例名称，以及仍有旧设置、资料或资源记录的名称不能用于新导入。

取消会停止该任务并清理本次未完成文件；其他下载继续运行。所有任务结束后自动退出任务界面。进入提交阶段后不能取消。清理失败或中断会显示「恢复 ZIP 导入」，请恢复后再启动游戏或写入该目录；发生外部修改时保留冲突文件并说明原因。

## 删除与恢复实例

1. 退出游戏，等待其他文件任务结束，在「实例设置 → 概览 → 高级管理」点击「删除实例」。
2. 核对实例名称、文件数量与大小后确认。整个实例文件夹会移入该游戏目录的可恢复区域，实例目录内的存档、模组和配置会一起保留；公共库、素材和共享游戏内容保持原位置。
3. 在「实例选择」的恢复记录中点击「撤销删除」，恢复原目录。关闭并重新打开启动器后，记录仍可使用。

实例描述、收藏、导出配置、内存与 Java 覆盖设置保留，恢复后继续使用。原名称在恢复前保留，不能再安装或改名为同名实例。请先恢复该目录内的已删除实例，再移除游戏目录登记；目录暂不可访问时，需要先恢复目录访问。若其他程序占用原位置，请先移开冲突目录，再刷新恢复记录；启动器不会覆盖它。恢复副本被修改时会保留文件并显示原因。

被其他实例继承或复用 JAR 的实例暂不能删除。位于实例内部且仍被选择或登记为可用运行环境的 Java 也需先移到实例之外并重新添加。符号链接、挂载点、读取失败或文件变化会阻止删除。

准备阶段可以取消；开始移动目录时取消按钮禁用。未完成的删除或恢复会显示「恢复实例删除操作」，请先完成恢复。当前不提供永久清空恢复区的按钮。

## 调整实例显示

打开「实例设置 → 概览」，在「个性化」中操作：

- 点击「修改实例描述」，输入描述并确认；支持多行，留空可清除。
- 选择内置图标或「自动」，选择实例列表的分类或「自动」。选择后即时保存。「自动」按检测到的加载器显示图标和分组。
- 点击「加入收藏夹」。收藏的实例在「实例选择」的收藏夹分组中置顶；点击「移出收藏夹」恢复普通分组。

实例列表会显示描述，搜索支持实例名和描述。分类控制列表分组，Minecraft 与加载器版本继续显示实际检测结果。

这些资料按登记的游戏目录和实例分别保存，关闭并重新打开启动器后仍保留。不同目录中的同名实例各自管理。

若保存时提示资料已经变化，点击「重新读取」查看最新资料，再重新编辑。游戏或文件任务进行时，需等待结束后保存实例信息。

## 修改实例名称

1. 退出游戏，等待当前文件任务结束，打开「实例设置 → 概览」。
2. 在「个性化」中点击「修改实例名」，输入新名称，再点击「检查改名」。
3. 核对旧名、新名及需要同步的引用实例，点击「确定改名」。完成后，返回概览查看新名称。

此操作会重命名物理实例文件夹和同名核心文件，并同步其他版本的继承与 JAR 引用。Minecraft 版本、存档、模组和配置保持原内容；启动器中的实例内存、收藏、描述、导出配置和资源删除记录会跟随新名称。

同名目标、已有目标资料、版本 JSON 中无法识别的自定义路径引用，以及实例内容中的符号链接或挂载点会显示原因并拒绝改名。请先处理这些问题，或使用其他名称。检查后文件变化时，需要重新检查。此功能需要支持 `openat2` 的 Linux 内核，以及支持 `O_TMPFILE` 的游戏目录文件系统。

准备阶段可以取消，取消完成后保留原实例；开始提交文件时取消按钮禁用。若出现中断，页面提供「恢复实例重命名」：未提交完成的文件恢复旧名，已提交的文件继续完成资料同步。原始核心备份保留在游戏目录内。待恢复目录暂时离线时，请先恢复目录访问。恢复完成前，保存设置、切换目录和文件操作会暂停；外部修改造成的冲突会保留文件并显示原因。

## 管理本地资源

打开所选实例的「模组」「资源包」或「光影包」页面。先退出游戏，并等待安装或其他文件操作完成。

- **启用／禁用模组**：悬停在模组行上点击对应按钮；也可选择多个模组，使用顶部批量按钮。禁用会将 `.jar` 改为 `.jar.disabled`，启用会改回 `.jar`。
- **导入**：点击「从文件安装」，通过系统文件选择器多选文件。模组支持 `.jar` 和 `.jar.disabled`，资源包与光影包支持 `.zip`。文件复制到该实例实际使用的资源目录，源文件保留。已有同名文件不会被覆盖，文件类型与归档格式会先检查。
- **删除**：选择文件并点击「删除」，核对确认框中的文件列表。删除的文件会保留用于恢复；点击「撤销删除」恢复最近一次删除，关闭并重新打开启动器后仍可使用。

若删除或恢复过程中发生冲突，先处理同名文件，再重新操作；启动器不会覆盖冲突文件。文件在选择后被外部程序修改时，需刷新列表后重新选择。标为「只读」的目录、符号链接或其他文件类型不能通过这些按钮修改。世界与服务器列表暂时仅供浏览。

资源位置遵循实例已有的目录隔离设置。多个实例共用资源目录时，启禁、导入和删除会影响使用该目录的其他实例。

当前删除需要资源目录与游戏目录位于同一文件系统；资源目录单独挂载时，操作可能被拒绝并回滚。

如果上一次资源操作未完成，页面会提供「恢复未完成操作」。恢复会尝试回到操作前的状态；遇到外部修改或同名冲突时会保留文件并显示原因。请先完成恢复，再启动游戏。

## 更新本地模组

1. 退出游戏并等待其他文件任务结束，打开「实例设置 → 模组」。启动器按文件内容检测 Modrinth 模组；「可更新」标签显示检测到的候选数量。
2. 在「全部」或「可更新」列表中选择需要更新的模组，点击底部「更新」。每批最多选择 64 个模组；必要依赖较多时可能需要分批。
3. 检查确认框中的旧版、新版、保留的启禁状态，以及必须替换、新增或复用的前置文件，再开始更新。
4. 「任务管理」显示信息检查、下载校验和文件替换。所有新文件通过校验后才替换原文件，并保留原文件恢复记录。
5. 需要撤销时，在模组页的「上次更新」旁点击「撤销更新」。撤销最新记录后可继续撤销前一次更新；更新后文件与相关资源目录必须仍与记录匹配。

当前检测使用 Modrinth 的文件哈希识别，选择匹配当前 Minecraft 版本和加载器的正式版本。未识别文件、重复项目、当前为 Alpha/Beta 的模组会显示原因，不按文件名猜测更新。检测结果只表示存在兼容候选；确认时仍会检查依赖与冲突，其他已装模组的固定前置版本可能阻止更新。

禁用模组保持禁用。已有禁用前置不会自动启用；包含禁用模组的更新批次若需要新增模组前置，会提示分开更新或先处理前置。可选前置不会自动安装。

提交前取消会清理本次暂存并保留原文件；开始替换后，取消按钮关闭，等待提交或恢复结束。更新与撤销记录随物理实例改名、删除恢复保留。外部修改或目录冲突会保留文件与记录并显示错误；未完成的事务通过页面顶部「恢复资源安装或更新」处理。共享资源目录中的更新会影响使用该目录的其他实例。

## 启动游戏

选择离线玩家或 Microsoft 正版账号，选好版本后点击「启动游戏」。启动器会先检查 Java 和依赖，再运行游戏。

离线身份适用于单人游戏和允许离线身份的服务器。正版登录、保存登录及头像与披风的使用方法见[账号说明](AUTHENTICATION.md)。

Java 默认按游戏要求自动选择，也可指定全局或实例 Java，见下节。Forge / NeoForge 实例需要匹配对应的 Java 主版本。

在「设置 → 启动」可选择默认实例隔离方式；「实例设置 → 设置」可为单个实例覆盖默认值：

- **自动识别**：实例目录下存在 `mods`、`saves`、`config` 或 `options.txt` 的普通文件或目录时，使用该实例目录；否则使用游戏根目录。
- **隔离到各自的实例目录**：游戏内容保存在 `versions/实例名/`。
- **共用游戏目录**：游戏内容保存在游戏根目录，资源变更会影响其他使用该目录的实例。

切换只改变后续启动和文件操作使用的目录，不会移动或删除原目录中的存档、模组或配置。切换后看不到旧内容时，可以改回原策略。启动、资源管理、日志、社区资源安装和导出采用同一策略。游戏或文件任务进行中，以及存在未完成恢复时，暂不能切换。隔离标记是符号链接、特殊文件或无法读取时会显示错误。

游戏窗口标题也可设置全局默认值，并为每个实例选择「跟随全局设置」「默认窗口标题」或自定义。填写自定义标题后点击「保存标题」，下次启动生效；默认模式保留游戏原标题。支持常规 LWJGL 2 / GLFW 字符串标题接口，包括 Wayland；模组绕过这些接口自行设置标题时可能不生效。此功能不会修改游戏 JAR。

「自定义版本信息」用于游戏接收的版本类型信息（`${version_type}`），与窗口标题分别设置；留空使用版本元数据中的原值。最多 256 个字符，不允许控制字符；只有使用该信息的游戏或模组会显示它。

### 额外启动参数

在「设置 → 启动 → 高级启动选项」填写额外 JVM 参数或游戏参数，点击各自的「保存」。实例设置中也有这两项：选择「独立设置」后填写并保存，留空可停用该实例的全局附加参数；选择「跟随全局设置」恢复继承。自定义版本信息也支持这两种范围。修改用于下一次启动。

- 参数以空格、换行或制表符分隔，单双引号可包含带空格的值，例如 `-Dexample.path="C:\Game Files\config"`。反斜杠可转义空格、引号和反斜杠，其他位置保持原样。
- JVM 参数追加在原版本参数后、游戏主类前；带值的 JVM 选项使用 `=`，例如 `--add-opens=java.base/java.lang=ALL-UNNAMED`。游戏参数追加在游戏参数末尾，选项使用双横线形式，例如 `--server localhost`；不接受单横线选项及受保护选项的缩写。
- 参数不会经过 shell，不展开环境变量、通配符或 `${...}`，也不执行命令。启动入口、classpath、账号、版本和内容目录由启动器管理；堆内存使用内存设置，不能通过附加参数覆写。显式窗口尺寸和 IP 偏好优先于附加参数。
- 每项参数文本最多 16 KiB、128 个参数，单个参数最多 4 KiB。保存时会检查分词和受保护选项，具体选项是否可用仍取决于所选 Java、游戏和加载器。

实例改名会同步这些覆盖设置的所属实例，但不会改写参数文本中自行填写的文件路径。

在「设置 → 启动」的「启动选项」中，可设置全局游戏窗口尺寸和 IP 协议偏好，保存后用于下一次启动：

- 窗口尺寸可选择默认、预设尺寸或自定义。自定义时填写宽、高并点击「保存尺寸」，单位为像素；宽度允许 320–16384，高度允许 240–16384。「默认」沿用游戏原来的窗口参数。
- IP 协议可选择 Java 默认、优先 IPv4 或优先 IPv6。优先设置仍允许另一种地址，并不会关闭对应协议；实际连接还取决于服务器地址和本机网络。

这两项作用于所有实例，也包含在启动器设置备份中。修改不会改变正在准备或运行的游戏；目前没有单个实例的覆盖入口。

## 检查启动环境

在「实例设置 → 概览 → 高级管理」点击「检查启动环境」，可查看实际游戏目录、所需 Java、当前 Java 的可用性，以及缺失的核心、支持库、原生库归档和资源文件。缺失项显示总数，展开后最多列出 32 个路径。启动失败后，主页也会为当前实例提供检查入口。

Java 存在问题时，点击「管理 Java」进入设置，下载栏会优先选择所需主版本。点击「开始下载」才会提交任务；官方目录没有对应版本时，可以手动选择或添加本地 Java。原有 Java 选择仍会保留，若实例指定了失效路径，可通过「实例 Java 设置」调整。

检查为只读诊断，Java 版本检查会运行有时间限制的探测进程。它检查文件是否存在并可作为普通文件使用；文件哈希、模组兼容性和游戏实际运行仍需另行验证。「测试游戏」保持实际启动行为。检查期间切换目录或修改配置后，请重新检查。

## 选择 Java

1. 打开「设置 → Java」，等待检测完成。列表显示本机可用运行环境的版本、架构、供应商和可执行文件路径。
2. 点击「自动选择」或一个 Java 条目，即时保存全局选择。自动模式优先使用满足要求的最低主版本。
3. 要添加其他安装位置，点击「添加」，通过系统文件选择器选择 Linux Java 安装中的 `bin/java` 可执行文件。检查通过后加入列表，再点击该条目选用。取消选择不会更改设置。
4. 需要新运行环境时，展开「下载 Java」，选择主版本并点击「开始下载」。目录来自 Mojang，每个主版本显示官方目录中最新的运行时；任务界面显示文件校验与运行环境检查。完成后列表刷新，原有 Java 选择保留，可继续使用自动模式或手动选用新条目。

下载的 Java 保存在启动器项目内的 `.pcl-rust/java`，可供多个游戏目录使用，不安装到系统目录。当前使用 Mojang 的 Linux x86 / x86_64 运行时；官方没有提供对应平台时，请通过「添加」登记系统 Java。下载任务沿用全局并发与速度设置；Java 任务之间顺序执行，可与其他游戏目录的下载并行。相同运行时已存在时不会覆盖。

取消会停止传输、删除本次未完成的暂存，然后退出任务界面，保留已安装的 Java。崩溃后留下的已识别暂存在下次 Java 下载时检查并清理。外部修改或不支持的暂存记录会保留并报错；此时按错误路径检查文件，不直接删除未知内容。当前不提供 Java 下载断点续传、自动升级或卸载入口。

在「实例设置 → 设置」的「游戏 Java」中，可选择「跟随全局设置」、「自动选择」或一个指定的 Java，即时保存。实例单独选择自动时，会使用自动匹配；相同名称的实例在不同游戏目录中分别保存选择。

自动选择下，启动前发现缺少适用 Java 时，会显示对应主版本的下载任务；完成后继续本次启动。取消下载或启动都会中止后续启动，已安装的运行环境可供下次使用。此自动流程用于启动游戏；整合包安装处理器缺少 Java 时仍可先在本页下载后重试。

自动发现会检查已下载 Java、项目及游戏目录的运行环境、`PATH`、`JAVA_HOME` 和 `/usr/lib/jvm`。加载器安装和组件重置会自动寻找处理器所需的 Java，也包含下载完成的托管运行时；游戏 Java 选择用于检查和启动游戏。

启动前会重新检查所选程序。手动路径失效、没有执行权限、架构不符或主版本不兼容时，启动失败并显示原因；设置会保留，可重新添加 Java 或改为自动。Forge / NeoForge 需要相同主版本，其他实例使用满足所需主版本的 Java。游戏运行或文件任务进行时，Java 选择暂不可修改。

旧设置升级前会保存备份。如果存在未完成的实例改名，请先完成恢复。手动登记的 Java 位于待改名实例内部时，需要先移到实例之外并重新添加，才能改名。

## 调整内存

- 在「设置 → 启动」的内存卡片中设置默认上限，点击「保存设置」。
- 在「实例设置 → 设置」的内存卡片中设置单个实例的上限，点击「保存」。该值会覆盖默认设置。

界面以 GiB 为单位。最大内存是 Java 堆的上限，不代表游戏启动时会立即占用全部额度。

## 启动遇到问题

打开「实例设置 → 概览」查看实例信息；「设置 → Java」可检查运行环境与当前选择。

启动失败后，点击启动页的错误提示打开诊断。预分析在本机完成，可识别部分 Java、缺失依赖、模组冲突、Mixin 和图形初始化错误；展开「查看线索」可读对应原文。线索不等于确定根因，无法判断时会明确提示。

新版本记录每次启动在日志中的起点，预分析只使用本次启动的有界尾部。旧监控记录没有起点时，界面标明「历史日志」，不把其中的旧错误当作本次失败的证据。

「导出诊断报告」将退出信息、预分析线索及已显示的日志摘录保存为 TXT；它不是完整原始日志。「AI 分析」使用 AI 管理中已保存并选中的预设，先显示目标模型、接口地址与报告内容，点击「发送并分析」后才会调用。分析支持停止，关闭诊断或离开当前失败记录也会取消任务。AI 只返回文字建议，不能操作游戏文件。

报告会过滤启动器已知的账号敏感字段，仍可能包含模组自定义输出或个人信息；分享或发送前可展开查看。AI 使用预设的调用与费用限制，实际费用以服务商账单为准。

如果当前选中的是失败实例，可直接进入「检查启动环境」；「查看 / 导出日志」会打开本次失败对应的日志。准备阶段尚未生成日志，或日志已被移走时会提示原因，不会改用另一轮启动的日志。也可随时通过「设置 → 查看日志」手动选择其他日志。

关闭再打开启动器后，可以恢复独立监控已记录的退出状态、实例与对应日志。旧版监控记录没有实例身份时，只恢复已知信息；需要手动选择实例，再从实例设置检查环境。开始新一轮启动后，上一轮退出记录不再作为当前失败恢复。尚未创建独立监控的准备阶段错误不会跨重启保存。

### 检查与补全缺失文件

点击「启动游戏」后，启动器先检查必需文件。没有缺失时正常启动；存在可补全项时，会显示文件补全任务，完成后继续本次启动，无需再点一次。取消本次启动或补全任务都会停止后续启动。没有下载依据的缺失项、元数据错误或下载失败仍会显示原因；自动选择 Java 时，若本机没有适用版本，会下载对应的 Mojang 官方运行环境后继续启动。手动指定的无效 Java 不会被自动替换。

在「实例设置 → 概览 → 高级管理」点击「检查启动环境」或「补全文件」。检查结果会显示 Java 问题和缺失文件；存在可处理的缺失项时，点击「补全缺失文件」开始任务。补全结束后可重新检查启动环境。

补全使用实例元数据中的下载信息，支持有可信来源、SHA1 和大小声明的游戏核心、支持库、当前平台原生库、资源索引、资源文件与日志配置。已有文件不会被替换，也不会修改模组、存档或游戏设置。已有的 Windows 游戏目录可能需要补充 Linux 原生库。

取消任务会清理未完成的下载，已经下载并校验完成的文件会保留供下次使用。缺少下载信息或无法自动补全的项目会显示在任务清单中；如果版本 JSON 已丢失、加载器需要重新运行安装处理器，仍需重新安装相应组件。自动补全只处理缺失文件，不替换已有文件；模组兼容性仍需另行排查。

需要检查已有文件时，在「检查启动环境」中点击「校验依赖完整性」。这是显式的本地检查，按元数据中的大小和 SHA1 校验游戏核心、支持库和资源，结果保留在任务管理中，可查看具体的缺失、损坏和无法校验项，读完后关闭卡片。没有完整校验依据的文件会单独标注；资源索引缺失、损坏或无法验证时，资源对象覆盖范围也会标为未完整检查。

需要修复时，点击「校验并修复损坏文件」。启动器重新校验声明完整且来源受支持的依赖，下载验证通过的替换文件，先保存原件备份，再逐个应用。任务结果会保留修复数量、备份目录和未处理项；缺失文件仍使用补全入口处理。备份位于对应游戏目录下的 `.pcl-linux/dependency-repairs`，不会自动清空。

取消会保留已提交的修复，恢复尚未提交的原件。断电或意外退出留下的记录会阻止该目录的启动与写入；在提示条点击「恢复未完成修复」完成恢复。外部修改或占位冲突会保留文件并报错，不强行覆盖。

这些入口不校验任意模组、存档及系统驱动。完整校验可能读取较多磁盘数据，因此不会在每次启动时自动运行。

当前补全操作需要 Linux 的安全目录和匿名临时文件能力。补全过程中暂不能进行其他文件任务或启动游戏；目录、实例元数据或设置发生变化时会停止，并保留已完成的文件。

在游戏内使用正常退出操作。启动器中的「结束进程」会立即结束游戏，未保存的进度可能丢失。

## 启动器设置

启动器偏好在「设置 → 管理、个性化、语言、杂项、软件更新」中保存，与游戏目录和账号分别管理。

### 外观、媒体与主页

「个性化」可调整浅色、深色或跟随系统主题、界面透明度、字体、窗口大小锁定、标题栏和启动提示。指针可选择蓝色渐变或简洁描边、小（24 px）或标准（28 px）大小，也可关闭自定义指针使用系统指针。文本右键菜单可切换舒适或紧凑间距；关闭后使用系统文本菜单，游戏目录的专用操作菜单仍保留。高级材质使用桌面 WebKit 支持的背景模糊，效果取决于窗口管理器。动画帧率与速度作用于启动器界面动画；系统减少动态效果设置优先。

背景和音乐分别放入其「打开文件夹」入口打开的目录，再点击刷新并选择文件。媒体格式能否播放取决于系统 WebKit 解码器；播放失败时会显示提示。网页预览不能代替实际桌面播放器验证。

主页可选择空白、内置预设、本地文件或 HTTPS 地址。本项目使用有限的 JSON 内容格式，支持文字与普通网页链接，不执行 HTML、JavaScript 或 CE XAML。自定义文件示例：

```json
{
  "schema_version": 1,
  "title": "我的主页",
  "sections": [
    {
      "title": "说明",
      "text": "欢迎使用启动器。",
      "links": [{"label": "项目主页", "url": "https://github.com/HyacineFengJin/PCL-RH"}]
    }
  ]
}
```

选好来源后通过页面的读取或刷新操作加载。导入启动器设置只恢复来源配置，需自行刷新内容。远程主页限制为公开 HTTPS 地址；使用代理时，地址校验可能拒绝读取并显示原因。

隐藏设置可收起主导航、子页和指定入口，不删除相关游戏内容。按 F12 临时显示隐藏功能；再次按下恢复隐藏状态。未开放的功能不会因临时显示而变为可用。

### 语言、网络与下载

界面提供简体中文和 English；区域格式可独立设置或跟随系统，影响数字与日期显示。资源作者提供的名称、说明和游戏日志保留原文。

代理可选择不使用、系统或自定义。系统模式读取进程的代理环境；自定义地址不接受账号密码。DoH 替换本机客户端的地址解析，查询失败时使用系统解析；HTTP 代理负责解析目标网站时，本机 DoH 不控制代理端解析。网络策略修改需等待游戏、文件任务、更新和登录结束。

最大线程数和速度限制作用于原版、加载器与 Modrinth 游戏文件下载，所有运行与等待中的下载共用一份文件并发和带宽预算。速度单位为 MiB/s，0 表示不限速；目录与元数据请求不计入此限制。这些下载策略需在任务全部结束后修改。禁止下载缓存复用关闭其他目录或项目缓存的复制，目标目录内已验证的完整文件仍可复用。数据源目前使用官方服务。

可关闭安装完成后自动选择实例。启动后的窗口行为支持保持显示、游戏运行期间隐藏，以及启动成功后关闭启动器。独立监控进程继续收集日志；重新打开启动器可查看并停止仍在运行的游戏。启动失败或取消准备时不执行成功后的关闭行为。

剪贴板资源识别默认关闭。启用后，仅在启动器有键盘焦点时识别标准 Modrinth 资源链接并打开现有详情页；不保存或上传剪贴板原文。公告来自本项目 GitHub Releases，可显示全部、仅稳定发行或不显示；没有公告和网络失败分别显示状态。

### Minecraft 版本提醒

在「设置 → 管理 → 游戏更新提示」分别开启正式版和快照提醒。两项默认关闭；首次成功检查只记录当前版本，之后按 Mojang 官方发布时间判断新版本。启用后启动器定期检查，重新获得焦点时也会检查是否已到时间；两个类型同时更新时合并提示。

提醒与当前游戏目录、实例无关，点击开关不会下载或安装游戏。已确认提示的版本保存在本地；设置备份只包含开关，不包含已读记录。关闭再启用时，最多提示各类型最新的未读版本。正式版本同时出现在官方的快照入口时，不会重复当作快照提示。

网络或本地记录不可用时会显示原因并保留已有记录。程序在提示显示后、确认保存前退出，下次打开可能再次提示该版本。

### 设置备份、诊断与应用入口

「杂项」可导出、导入启动器设置。备份包含外观、来源地址及各项启动器偏好；不包含账号凭据、游戏目录或游戏文件。导入前可检查内容，确认后保存旧设置备份。文件被其他程序修改或格式不受支持时，启动器保留文件并暂停覆盖，使用重新读取入口处理。

本地诊断默认关闭，只记录启动器事件、阶段、耗时与固定结果码，不向服务器发送。调试模式增加本地阶段记录；添加延迟作用于游戏启动准备，等待可取消。禁用硬件加速需重新启动启动器。

「停止使用」显示当前可移除的应用入口并请求确认；仅移除本项目拥有且未被外部修改的桌面文件，移入可恢复区域。游戏和账号保留。可以恢复已移除入口；包管理器安装的程序应通过对应包管理器卸载。统计入口显示本地实际打开启动器与成功启动游戏的次数。

## 日志管理

「设置 → 查看日志」可读取游戏日志，按设置限制实时显示行数，导出一个日志或全部日志 ZIP，或清理旧日志。正在写入的当前日志不参与清理。导出会对已知账号敏感字段脱敏。

选中日志后，可在内容区域输入关键词，切换是否区分大小写，并用「上一处／下一处」定位；输入框中也支持 Enter、Shift+Enter，Esc 清空。查找仅针对当前已加载的文本，按字面匹配，最多显示并定位前 1,000 处；达到上限时会提示缩小关键词。重新点击日志可读取最新内容，并清除上一轮查找。

清理先移入可恢复区域；恢复记录可在日志页查看。遇到外部修改会保留文件并显示冲突。长时间导出与清理可在任务管理中取消；启动器关闭时等待任务停止或完成恢复。

「实例设置 → 概览 → 高级管理 → 游戏日志」可查看游戏生成的日志与崩溃报告，支持普通文本日志和 `.log.gz` 压缩日志。先从列表选择文件，再查看与查找内容；使用共享游戏目录的实例会显示共享标识，这些文件不一定属于当前实例。

大段文本只显示末尾，并提示截断；压缩文件超过读取上限或损坏时会提示错误。游戏运行时也可读取；文件正在写入、轮换或被移走时，可能需要刷新列表再选择。这里列出的报告不会自动替代启动失败诊断所绑定的日志。

「导出当前文本」将已加载的脱敏文本另存为 `.txt`，压缩日志也导出为可读文本。若页面提示截断，导出仅包含当前加载的末尾内容。保存前文件发生变化时，请刷新并重新查看；已有目标文件不会覆盖，导出位置须在游戏目录以外。

## 更新启动器

「软件更新」检查本项目的稳定版或测试版发行，支持手动检查、自动提醒、或自动下载后提示。检查结果区分最新、没有可用 Linux 发行、网络失败与公共 API 限流。当前项目不使用 Mirror 酱 CDK。

便携构建只有在发行文件符合版本、架构、来源、大小、SHA-256 和 Linux 可执行格式检查时才允许安装。下载完成后仍需确认安装；原程序保留用于回退。安装后的磁盘版本与当前运行版本分别显示，需要重新启动才能运行新版本。重新启动后可确认使用新版本，或者回退原程序；中断的更新通过恢复入口处理。

包管理器安装与无法识别的安装位置不执行程序替换，应按页面说明通过安装渠道更新。


## 独立保存社区资源文件

在资源详情中选好版本和精确文件，点击「下载文件」，通过系统保存窗口选择位置，再核对文件、大小、校验值与目标路径并确认。Modrinth 使用 SHA-512，CurseForge 使用 SHA-1（服务启用后）。此操作不处理依赖或安装方案；保存整合包文件也不代表完成整合包安装。

「设置 → 管理」可选择原文件名或项目加版本命名，并切换模组列表按元资料或文件名展示。命名规则只改变独立保存的建议名称，安装到实例仍使用官方文件名。

快速下载可每次询问位置，或使用本次启动器会话中上一次成功保存的文件夹。没有记录时仍打开选择器，重新启动后重新选择。每次保存均可检查目标；已有文件不覆盖，请选择新的名称。

取消会清理匿名未完成文件并返回原资源页面。开始发布时关闭取消按钮；下载期间官方文件信息变化、文件校验失败或保存位置被替换时，会保留已有内容并显示原因。目标文件系统需要支持匿名暂存。

## 社区资源来源与匹配

「下载」中的社区资源可选择 Modrinth、CurseForge 或 MC百科。MC百科支持模组和整合包资料搜索；「全部」在按名称搜索时会查询百科的明确关联链接，将已确认相同的项目合成一条，详情页可切换文件来源或打开资料页。初始热门列表使用文件来源，百科热门条目可在其单独来源下浏览。

模组、整合包、数据包、资源包和光影列表底部提供「上一页」「下一页」及当前页码。修改来源、筛选或排序会回到第一页；编辑关键词后点击「搜索」开始新的检索。部分来源失败时，仍显示成功来源的结果和提示。下一页依据来源的真实分页信息开放，归并后条目较少或本页仅含之前显示的项目时，仍可继续浏览。

CurseForge 官方 API 最多提供前 10,000 个结果；MC百科支持浏览前 100 页。达到对应来源的边界时会显示提示，可缩小搜索范围；其他仍有后续结果的来源可以继续翻页。世界目录仍未接入。

同名项目不会自动合并。百科把多个分支或加载器移植版列在同一词条时，会保留独立项目。未取得关联证据的条目也可能暂时独立显示；这不是覆盖全站的固定映射表。

版本、加载器、标签和排序由支持这些条件的文件来源处理。百科不提供兼容性筛选；「全部」下它只提供匹配证据，不会增加未筛选的下载条目。某个来源不可用时，其余来源仍可显示结果。

CurseForge 服务目前等待开放。启用后可查看文件版本，并通过「下载文件」保存作者允许分发的官方文件；采用官方 SHA-1 校验，未完成的匿名暂存会在取消或失败后丢弃。暂不支持从资源详情直接安装到实例或解析其前置依赖；本地 CurseForge 整合包 ZIP 可在服务开放后通过「导入整合包」安装。无法下载的项目仍可打开其官方页面。

收藏仍使用 Modrinth 项目身份；跨站资源已关联到明确的 Modrinth ID 时，可共用同一条收藏。

## 社区资源收藏

在 Modrinth 详情页点击「收藏」，选择收藏夹后确认。已收藏的项目可移动到其他收藏夹或移出收藏。进入「下载 → 收藏夹」选择文件夹，点击项目即可读取当前详情；齿轮入口可新建、改名或删除空收藏夹，默认收藏夹保留。

本地 Mod 列表识别到对应的 Modrinth 项目后，也可选中一个或多个 Mod，使用底部「收藏」一次保存。多个文件属于同一项目时只保留一条书签。无法确认来源的文件不使用文件名猜测项目。

收藏记录属于启动器，切换游戏目录不会切换收藏夹。列表保留最近确认的项目介绍；打开详情时读取当前信息。文件被外部修改或格式不受支持时保留原文件并显示只读提示，修复后可点击「重新读取」。

## 导出资源信息

在实例的 Mod、资源包或光影页面选中文件，点击「导出信息」并选择新的 JSON 文件。未选中文件时，顶部按钮导出当前筛选结果。导出的信息包含原文件名、名称、版本、介绍、状态、文件大小与扫描指纹；不打包资源内容。

一次最多 128 个文件，单文件不超过 256 MiB、总计不超过 512 MiB。读取有时间限制，数量较多时可分批导出。文件或目录在选择保存位置期间发生变化时，需要刷新列表后重试。元数据不可解析时会说明原因，并保留原文件名与状态；已有目标文件不会覆盖。其他资源类型的信息导出尚未开放。

「下载新资源」会打开对应社区类别，并带入已知游戏版本和加载器条件；浏览不会自动安装文件。

## 百宝箱下载与图片工具

### 自定义 URL 下载

填写 HTTP 或 HTTPS 地址和完整文件名，通过「选择」指定保存文件夹，再点击「开始下载」，核对地址、文件名和目标后确认。地址的查询参数会在确认窗口隐藏，实际请求保留原地址。文件名不能包含路径，保存位置已有同名内容时需要换名。

任务使用启动器的代理、解析、并发和总速度限制；取消等待传输停止并丢弃未完成文件，再返回原页面。「打开文件夹」打开本次选择的下载目录。文件最大 2 GiB，保存目录需要支持匿名暂存。完成结果中的 SHA-256 是实际下载内容的校验和，不表示提供者签名。

### 成就图片与皮肤头像

成就生成器填写物品 ID、英文成就名和文字后可预览或保存 PNG。目前内置图像支持 `minecraft:grass_block`、`minecraft:command_block`、`minecraft:redstone_lamp`，也可填写不带命名空间的对应名称。未提供的物品图像会明确提示不支持。

皮肤头像生成器通过「选择皮肤」读取本地 PNG，可选 8–512 像素尺寸并保存真正的 PNG 头像。支持 64×64、64×32 及其整数倍皮肤，最大 2048 像素；头像包含正面头部和外层叠加，不上传或修改原皮肤。保存窗口取消时不创建文件，已有目标文件不会覆盖。

正版玩家皮肤查询、服务器查询与游戏垃圾清理尚未开放。

## RH Code 与插件

顶部紫色「RH Code」入口打开模组项目工作区，旁边的橙色入口管理插件；百宝箱位于「设置」。工作区支持可拆分区域、多个 AI 对话、源码编辑和版本／加载器目标，AI 预设由左下角设置管理。RH Code 按需加载，离开后满足保存与空闲条件时自动休眠。使用方法与当前范围见[RH Code 使用指南](RH_CODE.md)。

内置插件按「启动器」「RH Code」「两者」范围加载。社区页提供声明型插件及权限管理，插件市场暂未开放。旧制作器与搬运器项目从工作区项目列表的「旧版项目」打开，格式与能力范围见[旧版兼容功能](EXPERIMENTAL.md)。
